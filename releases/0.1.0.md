## General

### Jackson 3 support
This version contains experimental support for Jackson 3 which by default is required for Spring Boot 4. Even though not all Spring Boot 4 specific tests are already completed, with this version we want to give early adopters the change to test Jackson 3 / Spring Boot 4 migration on their side.

JEAF Generator is capable to generate Jackson 2 and 3 code within the same module. In order to make the behavior configurable we introduced several new configuration parameters: `jacksonVersions`, `jackson2Suffix`,  `jackson2Subpackage`, `jackson3Suffix` and `jackson3Subpackage`<br><br>For further details please look here: https://www.jeaf-generator.io/developer-guide/maven-plugin-configuration/#common-configuration-parameters<br><br>For better backward compatibility with existing implementations and tests we strongly recommend to apply the following configuration changes for Jackson 3

```java
// For better JSON backward compatibility with Jackson 2 we preserve the property order as it ws in Jackson 2
JsonMapper.builder().disable(MapperFeature.SORT_PROPERTIES_ALPHABETICALLY);

// If not working with generic builder pattern then in addition this setting is needed.
JsonMapper.builder().enable(MapperFeature.ALLOW_FINAL_FIELDS_AS_MUTATORS);
```

## Migration Notice

### Version 1.27.x or earlier

* **Upgrade of JEAF Generator Meta Model (JMM)**
  Due to implementation of [#337](https://github.com/anaptecs/jeaf-generator/issues/337) and [#624](https://github.com/anaptecs/jeaf-generator/issues/624) changes in JMM were necessary. Before switching to version `1.28.*` please upgrade your UML models to JMM Version `2.8.0` (revision `#271` or `#71` in MagicDraw Teamwork Cloud)

<br>

* **Required changes in UML model**
Due to [#492](https://github.com/anaptecs/jeaf-generator/issues/492) there are cases where you have to do changes in the UML model before upgrading. In order to fix [#492](https://github.com/anaptecs/jeaf-generator/issues/492) JEAF Generator no longer generates a custom implementation class in case of abstract classes with derived properties. If you still need this class then you have to set tagged value `hasCustomImplementation` to `true`in the UML model. If not you need to delete the currently generated custom class from your `src` directory as it will cause compile errors otherwise after the migration.

<br>

* **JEAF Generator Extension API v2**
JEAF Generator now also supports a new version `2` of its extension API. If you want to make use of it then you need to explicitly enable that by implementing [`JEAFGeneratorExtensionAPI.ext`](https://github.com/anaptecs/jeaf-generator/blob/main/jeaf-generator/src/main/resources/jeafgenerator/api/JEAFGeneratorExtensionAPI.ext) and return `2` as supported version.

<br>

### Version 1.28.x or earlier

* No special actions for migration needed
